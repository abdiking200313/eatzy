# Supabase local tooling

This directory is now a proper Supabase CLI project (`supabase/config.toml`,
generated by `supabase init`). Nothing about the migration chain changed —
`config.toml` just tells the CLI where things already live:

- `migrations/` — the tracked, ordered migration chain (unchanged).
- `seed.sql` — local/dev-only demo data, applied by `db reset` after
  migrations (see the file's own header comment). Never applied by
  `db push` or to production.
- `schema.sql` — a standalone provisioning script for a *brand-new* Supabase
  project (run once via the SQL editor), not part of the CLI's migration
  chain. See [[Architecture]] in the vault for why it's separate.

## Local workflow (once Docker is available)

```sh
# one-time: install the CLI (see https://supabase.com/docs/guides/local-development/cli/getting-started)
supabase start          # boots local Postgres + Studio + Auth via Docker
supabase db reset        # (re)applies schema.sql is NOT run automatically —
                          # apply schema.sql once by hand on a fresh project,
                          # then `db reset` replays migrations/ + seed.sql
supabase migration list   # compares local vs. remote applied migrations
supabase db diff -f <name> # generate a new migration from a schema change
```

`supabase start` requires Docker with outbound network access to pull the
Supabase service images. This repo's CI/sandbox environments may not have
that (Docker daemon present but image pulls blocked, or no Docker at all) —
in that case, use a plain local Postgres instead: `initdb`, apply
`schema.sql`, then each file in `migrations/` in filename order, then
`seed.sql`, all via `psql`.

## Linking to the live project (manual, human-only)

`supabase link` / `supabase db pull` against the real project requires live
project credentials and is **never** run by the automated board worker —
see issue #34 for the tracked follow-up (recovering table DDL, e.g.
`restaurant_locations`, that exists live but was never captured as a
migration). Do this yourself, locally, with your own Supabase access token.
